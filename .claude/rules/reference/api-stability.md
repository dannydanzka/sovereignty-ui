# API Stability & Versioning

> **APPLIES TO**: Everything exported by the 4 entry-point barrels
> **VERSION**: 1.0 | **UPDATED**: 2026-07-05

---

## Semver contract (pre-1.0)

While the library is `0.x`, minors may include breaking changes but they MUST be:

1. Documented in the changeset (migration note for consumers).
2. Coordinated — check consumer pins before merging (`dearadry`, `followme`, `sovertainty`, `desarrollemos`, `trackia` — see grep below).

```bash
grep '"@dannydanzka/sovereignty-ui"' ~/Documents/soverum/products/*/package.json
```

## What counts as breaking

- Removing/renaming a public export (component, hook, util, token helper, type).
- Changing a prop's type/semantics, removing a prop, changing a default that alters rendering.
- Renaming a `--sui-*` CSS variable or changing a token's meaning.
- Dropping a peer-dependency version range.

## What is safe (minor/patch)

- New components/patterns/hooks/utils/tokens.
- New optional props with backward-compatible defaults.
- Visual bugfixes that restore intended token behavior.

## Changesets (mandatory)

- Every user-visible change ships with `npx changeset` (patch/minor/major + summary).
- `CHANGELOG.md` is generated by changesets in CI — never hand-edit released entries (backfilling a missed release entry is allowed, flag it in the PR).

## Deprecation path

1. Mark with `@deprecated` JSDoc + keep working for at least one minor.
2. Mention replacement in the changeset.
3. Remove in the next coordinated breaking release.
